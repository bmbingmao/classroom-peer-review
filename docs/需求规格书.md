## 0. 硬性约束

1. **纯网页端**（PC + 手机浏览器自适应），无 App、无小程序。
2. **Node.js 全栈**；单机部署，50 人同时在线，轻读写。
3. `Dockerfile` + `docker-compose.yml`，一条 `docker compose up -d` 起来。能在 1Panel / 飞牛NAS / 裸 Linux / Windows Server(Docker Desktop) 任一环境跑。
4. 局域网使用，不强制 HTTPS，**监听端口可配**。
5. 多教师数据严格隔离：每人只见自己的组、评价项、评语、积分。
6. 匿名开启时，**前端不得向任何学生下发评委/被评者真实身份**（含接口字段、导出文件）。
7. 数据可导出 Excel；SQLite 与上传媒体落在可挂载卷。

## 1. 角色与权限

| 角色 | 来源 | 能力 |
|---|---|---|
| **admin** | 初始化内置一个（首次启动用环境变量设密码） | 开通/禁用教师、重置教师密码；配置全局 AI 兜底；查看系统状态。不参与教学 |
| **teacher** | 仅 admin 开通，不可自助注册 | 管理自己的组/文件夹；发起/管理/删除投票与评分；上传作品；看实时结果与图表；小眼睛看真名；放行/驳回待审评语；手动加减分；导出 Excel（含真名，留痕） |
| **student** | 教师导入（学号+姓名），初始密码=学号 | 改密；参与自己所在的组被邀请的活动；写评语；发表情；看匿名结果与评语墙；看个人积分与排行榜；看到期后自己的成绩（可配） |

**鉴权规则**
- 每个业务实体带 `teacher_id`（学生除外，见 §3.1）。所有教师侧接口在 SQL 层强制 `WHERE teacher_id = ?`，不靠前端过滤。
- 学生侧接口只校验"该学生是否在活动邀请的组里"，不返回他人身份。
- 越权一律 403，统一错误体 `{error:{code,message}}`。

## 3. 账号与登录

### 3.1 学生账号模型【拍板 + 定】

- **学生是全局实体**：`users.username`（学号）全局唯一，跨教师共用同一账号和密码。
- 教师与学生是**多对多**归属关系，记在 `teacher_students(teacher_id, student_id)`。
- 教师导入学号时：
  - 学号不存在 → 新建 `users` 记录 + `teacher_students` 关联，初始密码=学号，`must_change_pwd=1`。
  - 学号已存在（被本教师或其他教师关联过）→ **只加关联**，不改密码。UI 提示一句"该学号已存在，账号共用"。
- 登录入口统一：学号/教师账号 + 密码，命中唯一 `users`。
- 教师只能看到与自己有 `teacher_students` 关联的学生。
- **重置密码会全库生效**（同一账号）：UI 必须提示"该学生若同时在其他教师名下，密码同步影响"。
- **删除学生** = 仅解除本教师的 `(teacher, student)` 关联；账号不物理删除（保留历史评分/积分/评语）。无任何关联时账号 `status=disabled`。

### 3.2 登录与密码

1. 统一登录页，账号 + 密码。
2. 学生初始密码 = 学号，**首次登录强制改密**，未改密只能进改密页。
3. 改密必须验旧密码，新密码 ≥ 6 位。
4. 教师由 admin 创建（姓名、账号、初始密码），可禁用、可重置。
5. 登录限流：同一 IP + 账号 5 次失败冷却 5 分钟；失败计数落库，重启不重置。

## 4. 学生组（教师端）

- 建组（组名）。
- **导入学生**：①逐条加 ②粘贴批量（每行 `学号,姓名`，中英文逗号/制表符都认）③上传 CSV（UTF-8，自动跳首行表头）。导入结果必须回报：成功 N 条 / 已存在 N 条 / 格式错误 N 条（带行号）。
- 组操作：重命名、编辑成员、删除整组（二次确认，提示"组内学生账号保留，仅解除关联"）。
- 学生操作：改姓名、重置密码、移出组、解除关联（见 §3.1）。
- 一个学生可属于多个组。
- **一个学生可被多个组在同一活动里邀请**：去重，只算一次参与。

## 6. 投票模块

### 6.1 发起设置

1. 标题、说明（富文本，可插图/视频，见 §9）。
2. 选择参与组（可多选）。
3. 选项 ≤ 10 个，每个可配文字 + 可选配图。
4. 单选 / 多选；多选可设"最多选 N 项"（N ≤ 选项数）。**没有"总分"字段**（v1 已删）。
5. 开始时间 / 截止时间，到期**由后端自动关闭**（不依赖前端）。
6. 是否匿名。
7. 状态：未开始 / 进行中 / 已截止 / 教师手动关闭。

### 6.2 学生端

- 列表卡片：**未参与 = 深蓝，已参与 = 浅蓝**。
- 单选必选 1 项；多选至少 1 项，最多 N 项。三项校验服务端为准。
- **提交即完成参与**（+10 分）。
- **不允许撤回**；截止前可**修改**（覆盖原记录），修改不再发分。
- 匿名下也能实时看到各选项**票数**，看不到投票人。

### 6.3 教师端结果【拍板】

- **只展示：各选项票数 + 当前票数最高的选项高亮标记**（并列最高全部标记）。不做饼图、不算百分比。
- 参与率、已交/未交名单（匿名活动也显示"谁交了"，不显示"投了哪个"）。
- 可手动关闭、删除；进行中不允许改选项（只允许改标题/说明/延长截止时间）。

## 7. 评分模块（核心）

### 7.1 发起设置

1. 标题、说明（富文本）。
2. **唯一模式**：教师指定被评对象，不做全员互投。
3. **被评对象**：教师录入 N 个，每个绑定一件作品（图/视频/文字）并可关联一名学生；对外只显示匿名编号（作品A / 编号03）。`hidden=1` 的对象不透发给学生（用于教师自测或暂存）。
4. 选择参与组（评委来源）。
5. 是否匿名评分。
6. 开始/截止时间，到期自动关闭。
7. **评分项 ≤ 20 个**，每项：名称、`min~max`（整数，步进 1）、权重（数值，非负）。
8. **【定】不做"自评开关"**：被评对象绑定的学生**自动排除**在评委名单外（不评自己），v1 里"开放自评则计入"那句话作废。

### 7.2 学生填写与提交【拍板】

1. 逐个对象 × 逐个评分项打分（滑块 + 数字输入双通道，限制在 min~max 整数）。
2. 每个对象可写一条评语（§8）。
3. **必须打满才能提交**：应评对象集（`hidden=0` 且非本人绑定）× 全部评分项，缺任何一格，提交按钮禁用并提示"还差 X 格"。
4. 服务端二次校验：缺项 / 越界 / 非整数一律 400，并返回缺口清单。
5. **草稿**（P0）：每 3 秒或失焦自动存后端 `score_drafts`，换设备/刷新可续填。**草稿与正式分表分离**，正式分只在提交时原子写入（避免半截数据污染去极值统计）。
6. 提交即 +10。**不允许撤回**；截止前可修改（重新打满提交），修改不再发分，原 10 分不退。
7. 进行中**锁定** rubric 与对象列表（不允许增删评分项/对象），只允许改标题、说明、延长截止时间。
8. 卡片状态：未参与深蓝 / 已参与浅蓝。

### 7.3 去极值平均分算法【拍板 + 定】

对"某被评对象的某一个评分项"独立计算：

1. 取该对象该评分项下**所有已提交评委的分数**（草稿不算、弃权不算）。有效个数 = `n`。
2. **n < 5 → k = 0**（直接算术平均）。
3. **n ≥ 5 → k = max(1, ceil(n × 0.05))**，且**保证剩余个数 ≥ 3**：若不满足则 k 递减到满足为止。
4. 升序排序，**剔除最低 k 个 + 最高 k 个**。并列同分**按位置剔除**，不删光所有同分。
5. 排序键必须稳定：`(score ASC, student_id ASC)`。这样同分时剔除的是确定的那一条，重算结果可复现、导出标注不漂移。
6. 剩余分数算术平均 = 该项 **trimmed mean**。
7. 对象总分平均分 = `Σ(trimmed_mean_i × w_i) / Σw_i`。
   - **Σw = 0（教师全填 0）时按等权**，不报错不除零。
   - 权重为 0 的单项仍单独展示，不参与总分。

**示例（v1 的 19 人）**：19 ≥ 5 → k = ceil(0.95) = 1，去 1 高 1 低，剩 17 个取平均。

### 7.4 教师端结果

- 学生每提交一份，实时重算。
- 每个评分项显示：去极值平均分、原始平均分、有效人数 n、被剔除的极值（匿名编号 + 分数）。
- 图表（ECharts）：
  - **柱状图**：多对象在同一评分项上的平均分对比。
  - **雷达图**：单对象为中心，各评分项为维度。不做多对象雷达叠加。
- 下方评语墙（§8）。
- 小眼睛：评委/被评者身份隐藏/显示切换（走教师鉴权接口）。

### 7.5 被评者视角【定】

- 教师可开关"允许被评者本人查看自己作品的成绩与评语"（默认开）。
- 开启时：该学生能看到自己作品的各项均分、雷达图、评语墙；**看不到是谁评的**（即使非匿名活动也脱敏）。
- 关闭时：该学生与其他评委一样，只在结果页看到聚合数据。

## 8. 评语与 AI 审核

1. 学生在提交评分/投票时可写一条评语（每对象一条）。
2. 评语默认 `pending`，**审核通过才上屏**。
3. **异步审核**【定】：提交接口立即返回（评语入队），后台 worker 处理，前端轮询状态。**8 秒超时**，超时/断网/报错/JSON 解析失败 → 保持 `pending`，不报错、不阻塞提交。
4. 配置优先级：**教师自己的 AI 配置 > 超管全局兜底**。都没配 → 直接 `pending` 等人工。
5. 配置项：`api_base`、`api_key`、`model`（OpenAI 兼容 `/chat/completions`）。
6. 审核结果：`approved` / `rejected` + 违规类别，类别**固定枚举**：`辱骂 / 广告 / 色情 / 政治敏感 / 人身攻击 / 其他`。返回不可解析一律 `pending`。
7. **api_key 加密存储**：AES-256-GCM，密钥取环境变量 `APP_SECRET`；接口返回时永远脱敏为 `sk-****abcd`。
8. 开销控制【定】：同一活动 2 秒内的多条评语**攒批一次调用**（≤10 条/次）；单活动每天 AI 调用上限可配（默认 300 次），超限直接落 pending 并提示教师。
9. `rejected` 评语：学生侧不显示；教师侧折叠区可展开，标注 AI 类别/驳回原因。
10. 教师可对 pending 手动**放行 / 驳回**。
11. **热词云**：已通过评语做词频，Top 20，字号随频次（后端简单分词，中文用 `nodejieba` 或纯 n-gram + 停用词表，P2）。
12. **小眼睛**：匿名展示处放眼睛图标，教师点击切换真名/学号；学生端既无按钮也无数据。

## 9. 内容与媒体

- 富文本可插图片/视频（TipTap）。
- 限制（可配）：图片 jpg/png/webp ≤ 5MB；视频 mp4 ≤ 100MB。
- **图片必须上传 → 返回 URL → 富文本里嵌 URL**。禁止 base64 内联（会把库和接口撑爆）。
- 上传即校验 MIME + magic number，不只看扩展名；文件名随机化，禁目录遍历。
- 媒体存 `uploads/`，**经鉴权访问**（`/api/media/:id`），未登录 401，匿名场景不暴露上传者。
- 视频上传时读编码信息，H.265 提示"部分手机浏览器无法播放，建议 H.264"（警告不拦截）。

## 10. 积分与表情

### 10.1 规则【拍板 + 定】

| 行为 | 变动 | 约束 |
|---|---|---|
| 提交投票 / 评分 | +10 | 每活动每人一次；修改不再发 |
| 发任意表情 | −5（发送方） | 余额 < 5 不能发 |
| 收到**正面**表情 | +1（内容作者） | 同一人对同一内容**只加一次**（换 emoji 也算同一次） |
| 🚨 累计 | 不扣分 | 5 个**不同**学生发 🚨 → 自动折叠 + 通知教师 |

- **积分下限 0**：扣到 0 为止，任何途径不得为负。教师手动减分同样卡 0。
- **不能给自己内容发表情**。
- 每人每活动表情上限 20 个（防刷）。

### 10.2 十种表情

- 正面（作者 +1）：👍 赞、❤️ 喜欢、🔥 精彩、👏 鼓励、💡 有启发、😄 认可
- 中性/负面（不加分，只计数）：🤔 存疑、😐 一般、👎 不认可、🚨 警报

### 10.3 唯一键（v1 的漏洞，必须按此实现）

```
UNIQUE (user_id, comment_id)   -- 不含 emoji_type
```

同一人可改表情（覆盖），但**只有第一次加作者分**。否则点 6 个正面表情能白拿 6 分。

### 10.4 折叠与恢复

- 折叠后内容对所有人隐藏（含作者），教师可见。
- 教师可**一键恢复**（`folded=0`），恢复动作写 `moderation_logs`。
- 恢复后 🚨 计数保留，但不再触发折叠（避免反复）。
- 恶意折叠（5 人串通）：教师恢复即可，无需额外机制。

### 10.5 展示

- 每条评语/结果下可点表情，显示各表情计数。
- 学生端：个人积分、**按班级/课程维度的积分排行榜**（只展示，不计入成绩）。
- 教师端：手动加减分 + 必填原因，全部进 `point_ledger` 可查。

## 11. 实时计算

- 学生端 5s、教师端 3s 轮询；`document.hidden` 时暂停。
- 结果接口带 `version`（活动内的自增计数或 `max(updated_at)`），前端比对不变不重渲染。
- 教师端可手动刷新。
- 断网重试走指数退避（5s → 10s → 30s 封顶），恢复后立即拉一次。

## 12. 导出 Excel（教师端）【拍板：带真名】

- 单个评价项导出；按文件夹批量导出（多活动 = 多个 Sheet 组或分文件，默认分文件打包 zip）。
- **导出默认包含真实姓名 + 学号**。
- **必须二次确认**：弹窗写明"本次导出包含学生真实身份，将记录导出人、时间、活动"。写 `export_logs`。
- 文件命名：`{评价项标题}_{YYYYMMDD-HHmm}.xlsx`。
- Sheet 结构：
  1. **活动概览**：标题、类型、时间、参与率、匿名开关、是否导出实名。
  2. **投票明细**：各选项票数、占比、当前最高项；已交/未交名单（带真名）。
  3. **评分原始分明细**：评委（真名+学号）× 被评对象（匿名编号 + 真实关联人）× 评分项；**被剔除的最高/最低极值用底色 + 备注标注**。
  4. **去极值结果**：各项 trimmed mean、原始均值、有效人数 n、剔除数 k、权重、加权总分。
  5. **评语表**：内容、审核状态、违规类别、收到各表情数、折叠状态、作者（真名）。
  6. **积分表/流水**：个人积分、排行榜、每笔加减分与原因、操作人、时间。

## 15. 安全与非功能

**鉴权**
- bcrypt 哈希、改密验旧、登录限流。
- 角色中间件 + 每条 SQL 带 `teacher_id`，不靠前端过滤。
- 匿名字段在序列化层就剥离（不是前端隐藏）。

**传输与 Cookie 【定】**
- `COOKIE_SECURE` 可配，**默认 false**（局域网 HTTP 下设 true 会导致登录后 cookie 不发送 → 表现为"登录没反应"）。
- 反向代理下开 `trust proxy`，读 `X-Forwarded-Proto`。

**数据库 【定】**
- `journal_mode=WAL`、`busy_timeout=5000`、`synchronous=NORMAL`、`foreign_keys=ON`。
- **WAL 不能放网络文件系统**：数据目录用 named volume 或 NAS 本地 ext4/btrfs 路径，禁挂 SMB/NFS 共享。
- `better-sqlite3` 是同步的 → 大导出走 `worker_threads` 或分批，避免冻结事件循环。

**时间 【定】**
- 容器 `TZ=Asia/Shanghai`；DB 存 UTC 毫秒整数；前后端统一转换。
- 到期关闭由**后端定时任务**（每分钟扫一次）+ 查询时兜底判断，双保险。

**备份 【定】**
- 教师/超管可"一键备份"：`VACUUM INTO` 出快照 + 打包 uploads → 单个 zip 下载。
- **禁止直接 cp 正在写入的 .db 文件**（会得到损坏库）。

**校验**
- 选项 ≤10、评分项 ≤20、分数 ∈ [min,max] 且整数、权重 ≥0、多选数 ≤ N。
- 上传类型/大小/路径校验。

## 附：未采纳的方案（记录原因，避免反复讨论）

| 候选 | 未采纳原因 |
|---|---|
| Moodle Workshop | 匿名互评/rubric 都有，但去极值要改 PHP 核心，积分/表情/AI 审核全没有，等于框架里外挂两套系统 |
| iPeer (UBC) | CakePHP 2 老栈，无官方 Docker，停更 |
| 投票"总分"字段 | 与评分 rubric 功能重叠，会让发起页多一个没人填的框，还多一条导出岔路 |
| 自评开关 | 增加一个几乎不会用的配置项，默认"不评自己"已覆盖 |
| 撤回功能 | 需求方拍板：只能改，不能撤。少一个状态，流水更干净 |
| 多对象雷达叠加 | 视觉不可读，横向对比用柱状图 |
